## 15:34 WIB — arah desain tanpa perubahan router pengguna

Intent: catat klarifikasi pengguna bahwa router berbeda-beda dan tidak boleh
menjadi prasyarat konfigurasi deployment. Tinjau source endpoint dan referensi
primer untuk menjelaskan batas server-only dan kebutuhan enforcement endpoint.
Hanya memperbarui keputusan/handoff; tidak memasang firewall atau memutus akses.

Hasil: constraint desain berikutnya adalah tanpa konfigurasi router pengguna.
Model router tidak lagi menjadi blocker pembahasan. Usulan: Linux mengelola
CA/admission/policy/gateway internet dan admin; agent Windows menjalankan layanan
serta enforcement persisten agar trafik tidak bypass melalui NIC fisik saat
belum admission, tunnel berhenti, lease habis atau sertifikat dicabut. Router
hanya mengangkut trafik menuju server. Linux tidak bisa memblokir jalur internet
langsung pada perangkat yang belum dikelola/agent belum dipasang.

Status FITUR_BELUM_TERSEDIA: endpoint saat ini menggunakan helper tunnel di
vanguard/windows.py (install/uninstall tunnel service), belum memiliki persistent
internet lockdown terpisah. Profil /32 dan gateway/resource saat ini belum full
internet. Ini bukan klaim perubahan implementasi sudah selesai.

Kriteria desain: bootstrap terbatas untuk jaringan, server HTTPS/admission,
transport WireGuard dan DNS/waktu yang benar-benar diperlukan; kontrol IPv4 dan
IPv6; fail-closed setelah service berhenti/reboot tanpa membuka jalur biasa;
revocation harus ditegakkan gateway tanpa menunggu agent menerima push. Uji
koneksi aktif serta isolasi perangkat lain dan ukur jeda penerapan. Kebijakan
outbound harus dievaluasi terhadap aturan Windows/GPO yang sudah ada; rule
block-all sederhana dapat mengalahkan pengecualian allow. Siapkan pemulihan lokal
admin yang terautentikasi/tercatat tanpa membuka internet otomatis saat error.

Batas: sebelum agent/policy aktif, perangkat belum berada di bawah kontrol.
Administrator lokal penuh dapat merusak kontrol endpoint; jangan mengklaim
anti-bypass mutlak pada komputer pribadi yang tidak dikelola. Server admission
HTTPS dan WireGuard harus reachable; IP privat192.168.100.20 tidak otomatis
reachable dari router/jaringan rumah berbeda. Hosting Linux publik atau jalur
transport yang disediakan pengelola perlu ditentukan; tidak membutuhkan perubahan
router milik setiap client, tetapi jaringan yang memblokir transport tetap batas.

Referensi primer:
- https://git.zx2c4.com/wireguard-windows/about/docs/netquirk.md
- https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules

Keputusan tanpa perubahan router dicatat di VANGUARD_CONTEXT.md. Checkpoint dan
handoff menempatkan arahan baru di atas usulan gateway-router sebelumnya. Tidak
ada tes native baru, mutasi VM/router/host firewall, update installer, atau push.
Berikutnya bila implementasi dilanjutkan: spesifikasi mode endpoint terkelola,
prototipe terisolasi dan uji Windows10/11 sebelum rollout. Identitas/CA/6cek tetap.
