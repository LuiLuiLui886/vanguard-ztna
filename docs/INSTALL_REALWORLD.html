Pemeriksa integritas menolak hash berubah, file tambahan/hilang, symlink dan path keluar kit. Hasil PASS hanya integritas, bukan Windows/layanan sudah aman atau siap. 3. Siapkan Python dan WireGuard pada Windows

Unduh Python Windows installer64-bit seri3.13 dari halaman resmi Python; pilih installer penuh, bukan embeddable ZIP. Pada pemeriksaan22 Oktober, seri3.13 terbaru di halaman resmi adalah3.13.17; wheel kandidat dibangun untuk CPython3.13/win_amd64. Versi patch pada perangkat tetap wajib dicatat dan diuji, tidak otomatis dianggap lulus karena sama seri. Gunakan Custom installation, sertakan pip/venv, Install for all users ke C:\Program Files\Python313. Hindari mengubah PATH global jika aplikasi lain memakai Python; launcher menggunakan path absolut.

Unduh WireGuard dari halaman instalasi resmi. Operator memeriksa Authenticode valid dan publisher Python Software Foundation/ WireGuard sesuai artefak. Jangan mengambil installer dari tautan pihak ketiga atau menonaktifkan Defender/SmartScreen/execution policy. Jika kebijakan organisasi mengharuskan signing script, tanda tangani kandidat melalui proses organisasi sebelum uji; paket sekarang belum signed.

Contoh pemeriksaan sebelum menjalankan installer yang diunduh:

Get-AuthenticodeSignature -LiteralPath 'C:\lokasi\installer-yang-diunduh.exe' |
  Select-Object Status,@{Name='Publisher';Expression={$_.SignerCertificate.Subject}}

Nama/path di atas placeholder, bukan file yang disertakan. Hash resmi/publisher harus ditinjau operator; status valid tidak menggantikan pemeriksaan publisher. Jika runtime sudah ada, jangan downgrade atau menimpa runtime aplikasi lain. Gunakan path yang cocok prasyarat; versi/arsitektur lain adalah blocker kandidat.

Setelah pemasangan, operator mengonfirmasi sertifikat signer wireguard.exe yang terpasang lewat kanal tepercaya, termasuk thumbprint. Jangan menyalin thumbprint dari executable yang belum dipercaya lalu menyebutnya verifikasi independen.

& 'C:\Program Files\Python313\python.exe' -c "import sys,struct,venv,ensurepip; print(sys.version); print(struct.calcsize('P')*8)"
Get-AuthenticodeSignature -LiteralPath 'C:\Program Files\WireGuard\wireguard.exe' |
  Select-Object Status,@{Name='Publisher';Expression={$_.SignerCertificate.Subject}},@{Name='Thumbprint';Expression={$_.SignerCertificate.Thumbprint}}

Jangan mengimpor konfigurasi WireGuard manual/static peer. VanGuard mengelola service tunnel setelah admission, dan private key dibuat kemudian oleh client.

4. Backup sebelum perubahan aktif

Catat waktu dan baseline, ruang disk serta lokasi backup di inventaris privat. Saat guest mati, backup disk guest/UEFI/TPM serta XML melalui prosedur hypervisor; jangan menyalin disk yang aktif tanpa mekanisme konsistensi. Preserve seluruh enam VM, terutama CA dan identitas utama. Untuk upgrade aplikasi admin, gunakan backup service yang dihentikan seperti Bagian6. Backup bukan izin memulihkan CA lama.

Pada host, simpan XML/daftar disk, route, konfigurasi jaringan, ruleset host/libvirt, konfigurasi router dan akses pemulihan. Contoh keluaran hanya ke folder privat:

# HOST: baru snapshot read-only; tidak menyalakan atau mengubah jaringan.
umask 077
backup_dir="$HOME/VanGuard-Privat/pilot-$(date +%Y%m%d-%H%M%S)"
mkdir -m 700 "$backup_dir"
virsh -c qemu:///system dumpxml VM-CA > "$backup_dir/VM-CA.xml"
virsh -c qemu:///system domblklist VM-CA --details > "$backup_dir/VM-CA-disks.txt"
ip -j -4 address show > "$backup_dir/addresses.json"
ip -j -4 route show > "$backup_dir/routes.json"
# Ulangi XML/daftar disk untuk lima guest lain; simpan firewall via admin host.

Jangan mengunggah backup atau environment/database. Pastikan backup dapat dibaca, checksum cocok dan lokasi disk benar sebelum mengubah apa pun. Jangan restore index, serial, crlnumber, CRL atau database keamanan lama saat rollback aplikasi.

5. Siapkan jaringan khusus dan backend yang ada

  1. Hubungkan host dan PC ke LAN router, laptop ke SSID uji. Operator router menetapkan .50.1/24 dan reservation .50.10/.20/.30; hindari konflik DHCP/static. Default gateway endpoint .50.1. Jangan mengubah jaringan rumah/kantor utama.
  2. Host mendapat .50.10/24 pada Ethernet; backend libvirt tetap .100/24. Pertahankan Wi-Fi administrasi sampai jalur LAN/console teruji. Jangan bridge NIC backend, menghapus NAT libvirt, mengubah kernel atau memasang custom WireGuard.
  3. Setelah backup terverifikasi, nyalakan backend bertahap: CA, server, admin. Windows VM/client/attacker lama tidak wajib hidup untuk pilot ini. Periksa waktu/NTP, service readiness, freshness CRL dan disk/log. CRL kedaluwarsa harus diperbaiki lewat mekanisme CA yang sah; jangan melewati pemeriksaannya.
  4. Pada setiap endpoint, inspeksi adapter; tambahkan host route .100.20/32 melalui .50.10 pada adapter yang benar. Jangan membuat route default ke laptop host.
  5. Tinjau forwarding host/libvirt dan return path, kemudian firewall VM-SERVER. Dua sumber .50.20/.30 hanya boleh ke .100.20 TCP8081 dan UDP51820. Jangan buka CA8080/admin5000 atau aplikasi8082 langsung dari LAN. Admin tetap melalui jalur management host yang sudah ada.

Perintah tahap penerapan backend (jalankan satu per satu setelah backup):

# HOST: perintah ini menyalakan VM; hanya ketika tahap penerapan sudah dimulai.
virsh -c qemu:///system start VM-CA
virsh -c qemu:///system start VM-SERVER
virsh -c qemu:///system start VM-ADMIN

Jangan menjalankan start pada guest yang sudah hidup; cek virsh list --all. Di setiap guest, periksa service terkait; server juga vanguard-daemon/wg-quick@wg0. Tidak ada peer statis pada wg0. TLS/readiness harus diperiksa dari jalur yang memang diizinkan, misalnya server menuju CA dan admin menuju server.

# VM-ADMIN dengan trust anchor yang sudah dipasang melalui kanal tepercaya.
curl --fail --show-error --silent --connect-timeout 3 --max-time 8 \
  --cacert /etc/vanguard/root.crt https://192.168.100.20:8081/readyz

TCP berhasil/ping bukan bukti UDP siap. Rule backend/server-firewall.candidate.nft adalah bahan review, jangan langsung apply. Pastikan management IP .100.1 dan aturan layanan lama cocok, buat backup ruleset, jalankan nft syntax check di VM-SERVER, dan gunakan rollback terjadwal yang mempertahankan akses console. Host firewall belum diketahui backend/chain efektifnya; accept pada chain nft baru dapat tetap kalah oleh drop chain libvirt lain. Operator harus memeriksa ruleset aktual sebelum menentukan lokasi rule. Rincian matriks ada pada panduan pilot; tidak ada script host yang menebak aturan atau flush firewall global.

Contoh route sementara setelah interface dikonfirmasi, Windows Administrator:

Get-NetIPConfiguration
Get-NetRoute -AddressFamily IPv4
# Isi $ifIndex dari adapter LAN/Wi-Fi yang mempunyai IP endpoint yang disetujui.
New-NetRoute -DestinationPrefix '192.168.100.20/32' -InterfaceIndex $ifIndex `
  -NextHop '192.168.50.10' -PolicyStore ActiveStore

Jangan menambah jika sudah ada route identik. ActiveStore hilang saat reboot; uji ulang preflight setelah boot. Persistensi baru diputuskan setelah pilot lolos. Router tidak memerlukan static route backend jika kedua endpoint memakai /32 ini.

Jalankan pemeriksa host dari kit:

python3 checks/pilot_preflight.py

Script hanya membaca alamat, forwarding flag dan status6VM dengan batas waktu; tidak sudo, menyalakan guest, membuka port atau mengubah route. Exit2 berarti FAIL/UNKNOWN atau review manual masih diperlukan. Bahkan semua cek otomatis PASS belum membuktikan firewall/TLS/UDP/aplikasi. Gunakan report untuk memperbaiki prasyarat, bukan menganggap script gagal karena tidak mengembalikan ready.

6. Siapkan profil dan upgrade aplikasi admin

Profil kit menggunakan salinan root/public key lokal. Bandingkan lagi dengan layanan aktif: fingerprint root DER dan server WireGuard public key. Jangan membaca/mengirim server private key. Contoh read-only di node yang benar:

# VM-ADMIN atau VM-CA: fingerprint trust anchor publik.
openssl x509 -in /etc/vanguard/root.crt -outform DER | sha256sum
# VM-SERVER: hanya public key interface, bukan konfigurasi/private key.
sudo wg show wg0 public-key

Jika berbeda, berhenti dan telusuri asal/root/rotasi. Jangan menimpa trust agar cocok kit. Operator membangun ulang profil/kit dari root/key publik yang sah. Dengan routing .100.20, SAN HTTPS lama tetap sesuai; tidak perlu membuat CA baru atau mengganti sertifikat layanan hanya untuk pilot ini.

Kontrak server0.1.11 sudah mendukung admission/logout/resource gate yang diperlukan. Untuk bundle berprofil, VM-ADMIN perlu aplikasi0.1.12 dan environment baru. CA/server tidak perlu di-upgrade untuk sekadar menambah field profil pada bundle. Jangan menjalankan deploy/install.sh sebagai upgrade buta terhadap seluruh lab. Wheel backend di kit sama hash dengan wheel aplikasi pada paket Windows; dependensi aplikasi0.1.11 dan0.1.12 sama. Jika pip check gagal, hentikan upgrade dan tinjau runtime, jangan mengunduh/mengganti dependency diam-diam.

Operator menyalin wheel dan config publik ke /srv/vanguard-pilot/ pada VM-ADMIN, direktori milik root yang tidak writable akun biasa. Hash dicek terhadap manifest. Contoh urutan pada VM-ADMIN saja, setelah jalur pemulihan tersedia:

sudo systemctl stop vanguard-admin
# Pastikan inactive sebelum backup konsisten; jika stop gagal, jangan lanjut.
sudo systemctl is-active vanguard-admin

is-active harus menampilkan inactive (exit nonzero memang diharapkan). Backup root-only yang baru harus mencakup /opt/vanguard/venv, /var/lib/vanguard/admin, /etc/vanguard/admin.env, profil lama jika ada, dan unit. Hindari memasukkan isi environment ke terminal/log. Contoh backup konsisten, setelah admin inactive:

# VM-ADMIN: arsip memuat rahasia; hanya root, jangan dikirim bersama kit.
pilot_backup="/var/backups/vanguard-pilot/$(date +%Y%m%d-%H%M%S)"
sudo install -d -m 0700 "$pilot_backup"
sudo tar --acls --xattrs -cpf "$pilot_backup/admin-before.tar" -C / \
  opt/vanguard/venv var/lib/vanguard/admin etc/vanguard \
  etc/systemd/system/vanguard-admin.service
sudo chmod 0600 "$pilot_backup/admin-before.tar"
sudo tar -tf "$pilot_backup/admin-before.tar" > /dev/null
sudo sha256sum "$pilot_backup/admin-before.tar"

Jika arsip/checksum gagal, jangan upgrade. Arsip DB menjadi bukti pemulihan yang harus direview, bukan bahan rollback rutin. Setelah backup terverifikasi:

sudo /opt/vanguard/venv/bin/python -m pip install --no-index --no-deps \
  /srv/vanguard-pilot/backend/vanguard_ztna-0.1.12-py3-none-any.whl
sudo /opt/vanguard/venv/bin/python -m pip check
sudo install -o root -g vanguard -m 0640 \
  /srv/vanguard-pilot/config/profile.json /etc/vanguard/endpoint-profile.json
sudoedit /etc/vanguard/admin.env

Tambahkan tepat satu baris VANGUARD_CLIENT_PROFILE=/etc/vanguard/endpoint-profile.json; pertahankan semua nilai env lain, terutama secret/token. Jangan mengganti env dengan file contoh kit. Lalu mulai admin dan periksa readiness/bundle tanpa menerbitkan sertifikat uji pada health check:

sudo systemctl start vanguard-admin
sudo systemctl is-active vanguard-admin
curl --fail --show-error --silent --connect-timeout 3 --max-time 8 \
  --cacert /etc/vanguard/root.crt https://192.168.100.40:5000/readyz

Jika gagal, pertahankan log yang disaring, hentikan admin dan pulihkan runtime/env/ profil/unit dari backup kompatibel. Jangan rollback database/CA untuk membatalkan upgrade paket. Paket/backup/izin aktual harus diverifikasi operator; contoh di atas belum dieksekusi oleh kit.

8. Enrollment, login dan penggunaan oleh karyawan

  1. Kirim hanya request.json dari identity PC ke admin melalui kanal tepercaya. Lokasi identity: %ProgramFiles%\VanGuardEndpointData\identity. Jangan mengirim identity.key, wg.key atau employee-session.json.

  3. Admin mengunduh bundle publik hasil registrasi dan mengirimkannya ke PC. Import harus memakai identity asli yang membuat request. Bundle/profil/root berbeda ditolak; jangan memaksa overwrite. Jalankan:
& $launcher -Action import-bundle

Status file lokal atau service installed bukan bukti handshake/aplikasi.

  1. Admin memeriksa registered/lease valid/peer/handshake/transfer secara terpisah. Karyawan baru dapat mengakses demo setelah ada grant eksplisit yang sesuai. Ulangi untuk laptop Wi-Fi menggunakan -Role Laptop, identitas dan IP berbeda; PC harus lulus dulu sebelum keduanya dipakai bersama.

9. Siapkan resource demo dan buktikan akses

Pilot hanya mencakup HTTP uji10.8.0.1 TCP8082. Tidak menyediakan internet penuh atau aplikasi bisnis otomatis. Operator menjalankan demo sementara pada server melalui service yang dikelola; jangan menaruh data sensitif atau bind demo sebagai jalan pintas LAN. Admin/server menetapkan kebijakan tuple: device_id + username + internal-demo + 10.8.0.1 + tcp + 8082. Contoh demo sementara pada VM-SERVER setelah firewall gate terverifikasi. Salin hanya backend/demo/index.html publik dari kit ke staging operator. Gunakan folder baru milik pilot; jangan menimpa service/folder aplikasi yang sudah ada.

# VM-SERVER: mulai service demo hanya saat pilot; bukan bagian otomatis installer.
sudo install -d -o root -g root -m 0755 /srv/vanguard-pilot-demo
sudo install -o root -g root -m 0644 \
  /srv/vanguard-pilot/backend/demo/index.html /srv/vanguard-pilot-demo/index.html

Jika nama unit/folder sudah dipakai, inspeksi ownership sebelum menggunakan nama lain. Hentikan dengan sudo systemctl stop vanguard-pilot-demo setelah pengujian.

File kebijakan server mengikuti path VANGUARD_RESOURCE_POLICY yang dikonfigurasi pada server (umumnya /etc/vanguard/resource-policy.json), bukan profil client. Pertahankan grant lain yang masih sah; lakukan perubahan dengan validator kebijakan/prosedur server. Nilai karyawan aktual hanya inventaris privat.

Format satu grant (placeholder, bukan akun yang otomatis dibuat):

{"grants":[{"device_id":"ID_PERANGKAT","username":"AKUN_KARYAWAN","resource":"internal-demo","address":"10.8.0.1","protocol":"tcp","port":8082}]}

Siapkan kandidat file kebijakan privat yang mempertahankan grant sah lainnya. Validasi dengan loader aplikasi sebelum operator menerapkannya; output cukup jumlah grant, jangan cetak isi akun:

# VM-SERVER: validasi kandidat lokal, tidak memasang grant/peer.
sudo /opt/vanguard/venv/bin/python -c \
  "from vanguard.resource_policy import load_policy; print('policy valid; grants:',len(load_policy('/etc/vanguard/resource-policy.candidate.json')))"

Operator mempublikasikan file tervalidasi secara atomic pada path kebijakan yang sudah dikonfirmasi, mode0600/root. Daemon/renewal menyinkronkan set akses dari kebijakan+sesi/lease; jangan menambahkan elemen nft manual untuk melewati admission. Jika gate/env belum aktif, berhenti dan selesaikan rollout gate dengan backup; keberadaan file JSON saja tidak mengaktifkan enforcement.

curl.exe --connect-timeout 3 --max-time 8 http://10.8.0.1:8082/

10. Disconnect, logout dan pemulihan

Pada terminal pemilik, Ctrl+C meminta cleanup. Dari terminal administrator lain:

$launcher = Join-Path $env:ProgramFiles 'VanGuardEndpoint\VanGuard.ps1'
& $launcher -Action disconnect
& $launcher -Action logout

Disconnect menghentikan tunnel lokal, tidak mencabut token server. Logout mencabut sesi/challenge/lease terkait saja. Jika server tak terjangkau, pencabutan server belum terkonfirmasi; hubungi admin dan retry setelah konektivitas pulih. Jangan menghapus config ketika service/tunnel down belum pasti. Jangan taskkill massal.

Jika service hang (WIN-CLEANUP-02): cabut akses di server, verifikasi peer/grant hilang, identifikasi service/proses pemilik, pastikan teardown sebelum config diarsipkan. Jangan menimpa key atau menghapus VPN lain agar bisa connect lagi.

Setelah uji: cabut identitas/sesi/grant disposable, disable akun uji sesuai scope, hentikan demo sementara, hapus hanya route/rule pilot yang baru dibuat. Kembalikan config/runtime dari backup bila perlu, tanpa restore CA/database keamanan lama. Uninstall mempertahankan identity/config dan Python/WireGuard shared; decommission server harus dikonfirmasi dahulu. Lease/cert expiry, soak panjang dan media power-loss CA masih perlu pengujian terpisah sebelum klaim produksi.

11. Apa yang sudah siap dan yang belum

Source aplikasi0.1.12, paket offline Windows r3, public profile, wheel admin, generator firewall, pemeriksa read-only, template acceptance dan panduan tersedia. Kit dibangun/diverifikasi lokal; hasil terbaru dicatat pada CHECKPOINT/jurnal. Tidak ada credential/private key atau runtime installer dalam kit.

Belum selesai di target: native PowerShell/UAC/ACL/fresh/repair/upgrade/uninstall, runtime/signing sesuai kebijakan, kabel/router/IP pilot, host forwarding efektif, readiness live, registry alokasi .5/.6 dan pengujian dua endpoint. Jangan membuka layanan ke internet atau menganggap paket unsigned sebagai release produksi.

12.1 Urutan rollback yang harus dipahami sebelum mulai

Tetapkan siapa yang boleh menghentikan pilot dan di mana console tersedia. Rollback dimulai ketika kehilangan jalur administrasi, trust/key tidak cocok, default-deny gagal, identitas lain terputus oleh logout scoped, atau cleanup kepemilikan tidak pasti. Hentikan tahap berikutnya; simpan bukti tersaring.

  1. Cabut sesi/grant pilot melalui server/admin yang sah; verifikasi peer/aplikasi endpoint terkait terputus, pertahankan scope endpoint lain.
  2. Hentikan proses connect milik pilot. Konfirmasi teardown; jika gagal, tangani WIN-CLEANUP-02 dengan ownership terverifikasi sebelum menyentuh config.
  3. Hapus hanya route /32 dan rule bertanda pilot yang baru dibuat, memakai interface, next-hop atau handle yang dicatat. Jangan flush tabel global/libvirt.
  4. Bila upgrade admin gagal, pulihkan runtime/env/unit/profil kompatibel yang di-backup; pertahankan database/CA terkini dan histori pencabutan.
  5. Periksa lagi akses console/management, readiness, nol akses disposable dan identitas utama tetap. Catat hasil rollback, bukan hanya perintah yang dijalankan.

Jika tidak bisa memastikan restore runtime kompatibel, biarkan layanan terkait berhenti/fail-closed dan eskalasi ke operator. Jangan mengembalikan CA/database lama untuk mengejar hasil hijau.

Public key tetap metadata identitas; batasi penyebaran laporan sesuai kebutuhan. Handshake0 berarti belum pernah terlihat; waktu lama bukan bukti aktif sekarang. 13.2 Langkah native installer yang wajib dibuktikan

Lakukan pada identitas disposable, setelah baseline/backup. Rekam hash identitas sebelum/sesudah secara privat, bukan isi key.

  1. Fresh install di path terlindungi: exit0, runtime lengkap, belum ada peer/key yang dibuat installer. Configure/init adalah tahap terpisah.
  2. UAC dibatalkan: exit1223, tidak melanjutkan instalasi. Salah hash manifest: proses gagal, existing identity tidak berubah.
  3. Reinstall/repair: runtime baru lolos check sebelum pointer berganti; key/config tetap. Interupsi: status tidak boleh terlihat INSTALLED jika belum selesai.
  4. Upgrade ketika tunnel aktif: ditolak sampai pemilik menyelesaikan cleanup. Jangan menutup paksa aplikasi lain atau menghapus config.
  5. Path berspasi dan ACL: package/runtime terlindungi; reparse/junction ditolak; pengguna biasa tidak dapat membaca key atau menulis kode elevated.
  6. Uninstall setelah service absent: binary milik aplikasi hilang, data/key/config serta Python/WireGuard shared tetap. Decommission server diuji terpisah.

Checklist ini belum merupakan bukti bahwa hasil di atas sudah tercapai. Linux unit tests dan parse PowerShell tidak menggantikan eksekusi Windows native.

16. Operasi harian, shutdown dan pemeliharaan

16.1 Sebelum dipakai

Operator memastikan host mendapat daya dan tidak sleep, tiga backend tersedia, waktu sinkron, disk/log cukup, readiness dependency sehat serta CRL aktual. Admin meninjau sertifikat mendekati expiry dan akun/perangkat nonaktif. Karyawan memeriksa profil yang disetujui, login dan connect melalui launcher. Tidak perlu init, enrollment ulang atau generate CA setiap hari.

Jika certificate hampir kedaluwarsa, rencanakan penggantian immutable: siapkan key/ request baru pada client, ikuti alur replace admin setelah pencabutan lama sesuai prosedur, preserve histori/binding. Lease renewal tidak memperpanjang sertifikat. Jangan menimpa direktori identitas lama sebelum tunnel down terkonfirmasi.

16.2 Selama layanan dipakai

Bedakan domain running, service active, liveness, readiness, lease, peer, handshake serta transfer. Masing-masing menjawab pertanyaan berbeda. Pantau halaman penyimpanan operasional, pertumbuhan database/audit dan ruang disk; jangan menghapus log/database untuk membuat grafik terlihat baik. Rekam alasan gagal yang aman.

Untuk perubahan profil/port/trust atau upgrade runtime, buat window, backup dan uji kompatibilitas baru. Signing/hash paket harus diperbarui ketika isi berubah; jangan mengedit ZIP terverifikasi lalu memakai checksum sebelumnya. Hindari mengubah interface/IP aktif di tengah sesi tanpa rencana kehilangan koneksi.

16.3 Mengakhiri hari atau pilot

  1. Karyawan menutup akses aplikasi, disconnect lalu logout ketika server masih terjangkau. Admin memastikan lease/peer/grant terkait sudah dibersihkan.
  2. Selesaikan akun/identitas disposable dan hentikan demo sementara jika pilot selesai. Jangan mencabut identitas utama hanya untuk mematikan mesin.
  3. Simpan arsip audit dan laporan hasil. Backup terbaru mengikuti konsistensi aplikasi dan lokasi privat; tidak menggantikan histori backup sebelumnya.
  4. Operator menghentikan backend secara normal setelah memastikan tidak ada user aktif. Shutdown admin, server, lalu CA; konfirmasi keadaan guest sebelum host dimatikan. Hindari forced power-off sebagai rutinitas.
  5. Pada pemakaian berikutnya, urutan startup CA → server → admin dan verifikasi readiness diulang. Reboot bukan bukti revocation; fresh admission tetap wajib.

17.2 Penjelasan CA untuk penerapan ini

CA mengesahkan sertifikat perangkat/HTTPS; WireGuard memakai keypair terpisah. Private key X.509 dan WireGuard perangkat dibuat di perangkat. Admin mendaftarkan request/binding dan mengirim sertifikat publik, bukan membuat key milik karyawan. Sertifikat saja belum memberi peer: sesi karyawan dan enam pemeriksaan admission termasuk CRL/revocation/proof/binding tetap wajib.

Pada backend yang sudah ada gunakan CA yang sudah ada. Jangan menjalankan init untuk mengganti CA, memperbaiki CRL secara manual, menebak counter atau mengembalikan index lama. Domain/IP tambahan pada HTTPS memerlukan SAN dan allowlist operator; rencana saat ini tetap mengakses.100.20 sehingga tidak memerlukan CA baru.

Untuk lingkungan yang benar-benar kosong, prosedur lengkap generate CA, key/CSR HTTPS, signing, trust, CRL dan pemeriksaan sudah tersedia pada modul utama Bab5.3. Baca prasyarat lingkungan kosong dahulu. Untuk sistem ini jalur yang digunakan adalah verifikasi/pemeliharaan CA yang ada, bukan menyalin tahap init lab baru.

17.3 Batas klaim dan dokumen acuan

Paket ini mendukung persiapan pilot LAN/Wi-Fi terkontrol. Ia belum membuktikan kapasitas produksi, HA, akses internet publik, pengelolaan fleet besar atau semua jenis aplikasi/protokol. Resource gate yang dicontohkan khusus internal-demo TCP8082; menambah route/resource pada profil saja tidak membuat kebijakan baru. Prasyarat runtime, signing organisasi, native Windows dan topologi aktual wajib ditutup melalui pengujian target.

Gunakan checkpoint untuk status terbaru, panduan teknis pilot untuk matriks routing/firewall, API untuk kontrak layanan, keamanan untuk trust/lifecycle, dan Windows client untuk histori serta batas bukti guest. Jika revisi kit dan checkout berbeda, cocokkan hash serta tanggal; dokumen dalam ZIP adalah snapshot saat build, bukan status VM real-time.
